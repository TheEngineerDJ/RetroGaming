# RETROVAULT.md
## Living Product Bible
## Status: Draft v1.0 foundation

# 0. Name

Working name: RetroVault

Meaning:
- Retro = classic games, classic hardware, classic culture
- Vault = storage, trust, preservation, value, access

Future rename allowed only if:
- name still sounds premium
- name still fits preservation + knowledge
- name still scales beyond one app

Name must never feel childish, slang-heavy, or disposable.

---

# 1. Prime Directive

Build the most trusted retro gaming knowledge platform.

Not the biggest hype app.
Not the flashiest app.
Not the loudest app.

The trusted one.

Everything in this product exists to:
- preserve knowledge
- organize knowledge
- verify knowledge
- expose knowledge
- make knowledge useful

If a feature does not strengthen knowledge, it does not belong.

---

# 2. Product in One Sentence

RetroVault is a premium, data-rich retro gaming platform for collectors, players, repairers, modders, sellers, and preservationists.

---

# 3. What RetroVault Is

RetroVault is:
- knowledge engine
- collection system
- identification system
- price reference system
- benchmark system
- compatibility system
- preservation system
- accessory ecosystem
- future API platform

RetroVault is not:
- emulator frontend first
- social network first
- marketplace first
- content farm
- clickbait site
- ad machine
- AI hallucination machine

---

# 4. Core Promise

User opens RetroVault and gets:
- fast answer
- clear answer
- honest answer
- sourced answer
- useful answer

# 9. Product Philosophy

RetroVault is not a list of features.
RetroVault is a structure.

The structure must outlive any single device, emulator, or trend.

If a feature can be copied in a weekend, it is not the moat.
The moat is:
- data model
- trust model
- relationships
- verification
- quality of retrieval
- quality of presentation

---

# 10. Data Philosophy

Database is core.
UI is window.
AI is assistant.

Never reverse that.

Data must come before:
- screens
- AI prompts
- styling
- marketing
- monetization

If data model is weak, product weak.
If data model strong, product can grow.

# 12. Truth and Confidence

Every record has confidence.

Suggested scale:
- 100 = verified
- 75 = highly likely
- 50 = plausible
- 25 = weak
- 0 = unknown

Unknown is allowed.
Unknown is honest.
Unknown is better than fake certainty.

Disputed claims stay visible.
Competing claims stay visible.
History stays visible.

---

# 13. Preservation Rules

Never delete facts casually.
Archive instead.
Version everything.
Keep old state accessible.
Keep sources attached.
Keep competing claims if unresolved.

A broken link is still history.
A deprecated revision is still useful.
A bad listing can still teach something.

# 20. Entity Relationship Rules

Everything links.

Examples:
- game -> console
- game -> region
- game -> publisher
- game -> manual
- game -> price records
- game -> benchmarks
- cartridge -> game
- cartridge -> pcb revision
- handheld -> accessory
- handheld -> benchmark
- firmware -> hardware
- repair guide -> hardware
- accessory -> compatible hardware
- price record -> region
- benchmark -> device + firmware + test method

No orphan items unless explicitly unsupported.

# 21. Region Rules

Region matters.

USA ≠ Europe ≠ Japan ≠ Korea ≠ Australia.

Never merge by accident.
Never flatten by laziness.

Region affects:
- release dates
- box art
- manuals
- languages
- versions
- prices
- labels
- revisions
- compatibility
- collector value

---

# 22. Condition Rules

Condition is separate from identity.

Suggested condition bands:
- sealed
- mint
- excellent
- good
- fair
- poor
- broken
- repro
- custom

Condition must not erase history.
Condition must not erase region.
Condition must not erase variant.

# 23. Price System

Price data must preserve:
- currency
- region
- condition
- date
- source
- marketplace
- shipping if known
- sale vs listing
- confidence

Never present one average as truth.

Better:
- low
- median
- high
- sample count
- region split
- condition split
- recency

Benchmarks must be repeatable.

Track:
- boot time
- load time
- battery runtime
- heat

- audio latency
- input latency
- frame stability
- emulator accuracy
- crash frequency

Each benchmark needs:
- hardware
- firmware
- software version
- test method
- environment
- date
- source

# 25. Compatibility System

---

# 27. AI Rules

AI is allowed to:
- search semantically
- summarize source clusters
- OCR text
- detect probable matches
- suggest duplicates
- help classify images
- translate text
- spot likely fakes

AI is not allowed to:
- invent facts
- invent values
- overwrite verified records
- silently merge records
- pretend uncertainty is certainty

Any AI output must be labeled when needed.
