# PRODUCT_ROADMAP.md

**Project:** RetroVault
**Role:** Strategic sequencing
**Authority:** `CONSTITUTION.md`

## 1. Roadmap rule

Roadmap is a sequence of validated capabilities, not a promise to build every idea.

The Constitution outranks this roadmap.

## 2. Phase 0 — Foundation

Goal: establish trustworthy identity infrastructure.

- domain model
- SQLite persistence
- DAT ingestion
- hash engine
- candidate resolver
- SAF scanning
- rename planning
- audit journal
- Compose workflow
- test corpus

Exit condition: real Android device can safely identify and rename known ROM files.

## 3. Phase 1 — ROM Intelligence

Goal: make identification genuinely useful on messy real-world collections.

- broader No-Intro coverage
- broader Redump coverage
- platform-specific DAT handling
- better scene naming normalization
- patch/translation detection
- duplicate detection
- archive-aware collection analysis
- user review memory
- match explanation improvements
- import/export of identification decisions

Exit condition: materially better results on real mixed collections without increasing false positives.

## 4. Phase 2 — Collection Intelligence

Goal: turn files and physical objects into a coherent collection.

- canonical collection
- missing-item detection
- duplicate detection
- region/variant awareness
- physical collection records
- ownership state
- acquisition history
- condition
- authenticity
- collection statistics

## 5. Phase 3 — Hardware Knowledge

Goal: connect software knowledge to physical hardware.

- console models
- revisions
- accessories
- controllers
- compatibility
- firmware
- known faults
- repair references
- PCB information

## 6. Phase 4 — Preservation Graph

Goal: make provenance and historical context first-class.

- evidence records
- source snapshots where permitted
- historical claims
- scans and photographs
- preservation workflows
- correction history
- archival exports

## 7. Phase 5 — Market Intelligence

Goal: provide useful value context without becoming a marketplace.

- historical sales observations
- asking prices
- condition normalization
- completeness normalization
- regional pricing
- trend analysis
- scarcity observations

No manufactured rarity.
No artificial price scores.

## 8. Phase 6 — Benchmark Intelligence

Goal: make hardware/software performance measurable.

- benchmark definitions
- test methodology
- hardware configurations
- firmware versions
- repeatable measurements
- historical comparisons

## 9. Phase 7 — Community Knowledge

Goal: expand coverage without sacrificing trust.

- contributor profiles
- evidence submissions
- correction workflow
- specialist reputation
- review queues
- attribution
- moderation

## 10. Phase 8 — Interoperability

Goal: make RetroVault useful beyond its own interface.

- versioned API
- open exports
- emulator metadata integrations
- collection-manager integrations
- preservation-tool integrations

## 11. Deferred ideas

The following require strong evidence before prioritization:

- social feed
- marketplace
- advertising
- generic AI chatbot
- automated web scraping at scale
- speculative valuation
- user-to-user trading
- cloud ROM storage

## 12. Prioritization filter

Prioritize work that increases:

`trust × coverage × usefulness × defensibility`

while minimizing:

`complexity × operational cost × false-positive risk`

## 13. Roadmap discipline

A feature does not move forward because it is technically interesting.

It moves forward because it strengthens the product.

## 14. Guiding rule

**Build the foundation that makes future capabilities cheaper, safer and more powerful.**
